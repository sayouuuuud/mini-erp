# الاختبارات

استخدم Node.js 24 أو أحدث، ثم `npm ci`.

## الاختبارات المعزولة

```bash
npm test
npm run test:ui
```

تغطي المجموعة الأساسية الأقسام المتاحة، والتخزين الذري، والصيانة، والاسترداد مرة واحدة، ومحاسبة الاحتيال، ودورة المحافظ، وحدود الاستلام، وفحص بيانات الدخول المضمنة. تستخدم اختبارات الواجهة React DOM وjsdom، وتشمل استعادة الجلسة وسجل الإجراءات والورديات المحفوظة وتسوية الخسائر. أدوات `esbuild` و`jsdom` معرفة ضمن تبعيات التطوير.

يمكن تشغيل اختبار بعينه من أوامر `test:*` في `package.json`. يشغل اختبار سجل الإجراءات أداة بناء في الذاكرة؛ لا يحتاج مجلد Vercel أو ملف bundle محفوظًا.

## اختبارات التكامل والتدقيق التاريخية

- `npm run test:wallet-rpc` يحتاج ملف QA خاصًا في `ERP_QA_FIXTURE` يحوي النطاق والحسابات المجهزة للاختبار. لا تضع بيانات دخول في المستودع.
- ملفات `test_*audit.ts` وبقية ملفات TypeScript تحفظ سيناريوهات تدقيق تاريخية، وبعضها يخص أقسامًا أزيلت من التنقل. ليست كلها متوافقة مع واجهات النظام الحالية، ولا تدخل في `npm test`.
- اختبارات Supabase المباشرة مثل `test_supabase_live_integration.ts` و`test_realtime_transport.ts` قد تكتب سجلات؛ راجعها واضبط اتصال قاعدة اختبار قبل تشغيلها.
- اختبارات PostgreSQL موجودة في `supabase/tests/`. بعض الملفات تحتوي قوالب تحتاج تجهيز بيانات أو هويات QA قبل التنفيذ؛ لا يشغلها أي أمر اختبار افتراضي.

فحص بيانات الدخول المحلي يفحص شيفرة `src/` و`tests/` بحثًا عن قيم دخول ثابتة، ويعرض مسارات وأسطر فقط. لا يغني عن فحص الأسرار الخارجي أو مراجعة تاريخ Git.
